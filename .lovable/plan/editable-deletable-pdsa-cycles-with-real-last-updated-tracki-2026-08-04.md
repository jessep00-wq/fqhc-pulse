# Editable, deletable PDSA cycles with real "last updated" tracking

Cycle fields are already editable inline in the detail dialog and every change is written to the immutable `record_revisions` log. What's missing: a stored last-updated time, a delete path, "edited after completion" indicators, and sorting by activity.

## 1. Last updated

- Add `updated_at` to `pdsa_cycles`, maintained by a database trigger so it moves on any field change from any source (app, wizard, future automations).
- Surface it as "Last updated: <date, time>" next to "Started: <date>":
  - cycle detail header,
  - cycle card in the Kanban/list view (with a muted "stale — no updates in 14+ days" hint),
  - evidence document cover page.
- Existing rows backfill from the newest entry in the revision log, falling back to `created_at`.

## 2. Edit tracking and stage badges

- Editing is unrestricted at every stage, including stages already complete — no locking. (This already works; the change is what surrounds it.)
- Stage completeness, completeness %, and out-of-sequence warnings continue to be recomputed live from `pdsaProgress` on every edit, so a stage badge flips immediately if an edit empties a required field.
- New "edited" indicator: a small pencil chip next to a field label when that field has at least one revision recorded after the cycle first reached a state where its stage was complete. Same chip rolls up onto the stage tab so a reviewer can see at a glance that Study was revised post-completion. Hovering shows "Edited <date> by <name>" and clicking jumps to the History tab.
- History tab already lists all field edits; it will now also show edits flagged as post-completion revisions.

## 3. Delete (soft)

- Soft delete: `deleted_at` + `deleted_by` on `pdsa_cycles`. Deleted cycles disappear from the board, lists, chain pickers, reports, and export packets, but the row and its revision history survive so previously exported PDFs remain traceable.
- Delete action in the cycle detail dialog header menu and on the cycle card's overflow menu.
- Confirmation modal: "This will permanently remove this cycle and all linked tasks, evidence files, and history from your workspace. This cannot be undone."
- If the cycle sits in a chain, the modal adds an explicit chain warning naming the prior and/or follow-on cycle titles. On confirm, the adjacent cycles' `previous_cycle_id` / `next_cycle_id` are rewired to each other (or cleared when only one side exists), so no cycle keeps a pointer to a deleted record.
- Linked tasks are soft-hidden alongside the cycle rather than hard-deleted.

## 4. List view sorting

Add "Last updated" and "Least recently updated" to the existing sort control (newest / oldest / due), URL-synced like the current options, so stale cycles are one click away.

## 5. Evidence document

Cover and page footers replace the single "Generated by MeasureWise on <date>" line with two distinct fields: **Cycle last updated** and **Document generated**, plus a warning chip when the export is generated more than 30 days after the last cycle update ("cycle data may be stale").

## Technical notes

- Migration: `pdsa_cycles` gains `updated_at timestamptz not null default now()`, `deleted_at timestamptz`, `deleted_by uuid`; a BEFORE UPDATE trigger sets `updated_at = now()` whenever any tracked column changes; backfill `updated_at` from `max(record_revisions.created_at)` per cycle. Add a partial index on `(organization_id) where deleted_at is null`. RLS policies extended so soft-deleted rows aren't readable through normal list queries — filters also applied explicitly in every cycle query per the project's data-isolation pattern.
- `src/lib/pdsaProgress.ts` stays the single source of truth; it gains a helper that maps revision-log entries onto stage keys so the "edited after complete" flags derive from the same module rather than a parallel computation.
- Touched files: `src/pages/PDSALab.tsx` (queries, sort options, card metadata, delete from card), `src/components/PDSADetailDialog.tsx` (header timestamps, delete menu + confirm dialog, edited chips), `src/components/pdsa/CycleChain.tsx` (skip deleted, chain rewire helper), `src/components/pdsa/CycleEvidenceDocDialog.tsx` (cover/footer dates), `src/lib/cycleHistory.ts`, `src/lib/pdsaProgress.ts`, `src/components/pdsa/PDSAFilters.tsx`.
- Anything else reading cycles (QI report builder, OSV packet, network rollup, MCP tools) gets the `deleted_at is null` filter in the same pass.
